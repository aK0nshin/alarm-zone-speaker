# alarm-zone-speaker

Спикер для игровой системы видеонаблюдения.
Ловит сигнал с камеры о том, что нарушитель и трубит тревогу о конкретнойзоне.
Периодически говорит рандомные фразы.

## Настройка

Все настройки конкретного спикера лежат в [include/Config.h](include/Config.h).
Перед прошивкой надо их пошукать.

## Логика

Спикер работает вокруг очереди событий.

С очередью работают несколько конвееров:
1) Первый слушает радиомодуль и кладёт в очередь событие об аларме в конкретной зоне.
2) Второй разгребает очередь и воспроизводит аудиотреки в зависимости от событий. Он также подкладывает событие о воспроизведении неважной фразы в очередь по таймауту.

- При старте играет приветственное сообщение.
- Если играет тревога - таймер неважных фраз отсчитывается заного.
- Если сейчас играет тревога - неважная фраза скипается.
- Если случилась тревога - неважная фраза прерывается.
- Каждый спикер знает какой группе он пренадлежит из настроек. Чтобы спикер принял сообщение от камеры - в них должна быть зашита одна и таже группа.
- При разработке передатчика нужно использовать [общий радиопротокол](lib/RadioProtocol/README.md).

## Подготовка звуков

Звуки находятся в папке [data](data).

| Файлы в data/ | Назначение |
| --- | --- |
| `territory.mp3` | Стартовое сообщение |
| `camera.mp3`, `01.mp3` ... `06.mp3`, `intruder.mp3` | Составные части сообщения о тревоге |
| `phrase_01.mp3` | Фоновая фраза |

Они в формате MP3: моно, 24 кГц, постоянный битрейт 64 кбит/с, без ID3-тегов и Xing/LAME-заголовка.
Чтобы сделать такой формат, можно внутри докер контейнера выполнить команду: `ffmpeg -hide_banner -loglevel error -y -i data_src/v1/Camera.wav -map 0:a:0 -ac 1 -ar 24000 -c:a libmp3lame -b:a 64k -map_metadata -1 -id3v2_version 0 -write_id3v1 0 -write_xing 0 data/camera.mp3`

С учётом размера файлов и переразметки памяти, на устройство влезет примерно **5-6 минут** звукозаписей.

## Железо и схема

- ESP32-C3 Super Mini.
- Радиомодуль nRF24L01+ и совместимый передатчик команд.
- Аналоговый усилитель LM4871, динамик и подходящее питание.

Схема находится в [diagram.json](diagram.json)

## Прошивка (+ сборка)

### Способ 1: Docker и браузер

#### Подготовка и сборка

Установите и запустите Docker Desktop с Linux-контейнерами. Для прошивки понадобится Chrome или Edge с поддержкой Web Serial. Для скачивания образа, инструментов и зависимостей нужен интернет.

Соберите образ окружения. Повторяйте этот шаг после изменения `Dockerfile`:

```powershell
docker build -t pio-esp32 .
```

Запустите полную сборку и скопируйте служебный образ загрузки из того же контейнера:

```powershell
docker run --rm -v "${PWD}:/workspace" pio-esp32 /bin/bash -c 'bash ./rebuild.sh && cp /root/.platformio/packages/framework-arduinoespressif32/tools/partitions/boot_app0.bin .pio/build/esp32-c3/boot_app0.bin'
```

После успешного завершения файлы находятся в `.pio/build/esp32-c3/`. Контейнер удаляется, результаты остаются в папке проекта. Кэш инструментов контейнера не сохраняется: следующая сборка может снова скачивать зависимости.

#### Первая прошивка

1. Подключите плату по USB. Закройте программы, занимающие её последовательный порт.
2. Откройте [ESP Tool от Espressif](https://espressif.github.io/esptool-js/), нажмите **Connect** и выберите порт платы. Проверьте, что определён ESP32-C3.
3. Если подключение не удаётся, удерживайте **BOOT**, нажмите и отпустите **RST**, затем отпустите **BOOT** и подключитесь снова.
4. Добавьте все файлы из таблицы ниже. Используйте файлы одной сборки.
5. Обязательно выберите **Flash Mode: `dio`**: на используемой плате прошивка проверена именно с этим режимом. **Flash Frequency** и **Flash Size** оставьте в значении `keep`.
6. Нажмите **Program** и дождитесь завершения записи. Затем нажмите **RST** без удержания **BOOT**.

| Файл из `.pio/build/esp32-c3/` | Адрес |
| --- | --- |
| `bootloader.bin` | `0x0000` |
| `partitions.bin` | `0x8000` |
| `boot_app0.bin` | `0xe000` |
| `firmware.bin` | `0x10000` |
| `spiffs.bin` | `0x110000` |

Адреса соответствуют [partitions.csv](partitions.csv) для ESP32-C3 с Flash 4 МиБ. После изменения платы или разметки их необходимо проверить заново по настройкам и выводу PlatformIO. Старый скриншот `writing.png` не является инструкцией по прошивке.

**Переход со старой разметки:** SPIFFS перенесена с `0x290000` на `0x110000`.
Пересоберите программу и файловую систему. Для чистого перехода сохраните нужные
данные с платы, выполните полное стирание Flash и запишите весь комплект из таблицы.
Стирание удаляет также сохранённые настройки. Обновления только программы недостаточно;
старые адрес и образ SPIFFS больше не используйте. В PlatformIO после стирания
выполните обе команды `upload` и `uploadfs` из следующего раздела.

**Erase Flash** полностью удаляет программу, загрузчик, таблицу разделов, звуки и сохранённые данные. При переходе с другой прошивки или смене разметки можно начать с полного стирания, после которого обязательно записать весь комплект из таблицы. Для обычного обновления стирание не требуется.

#### Последующие обновления

При неизменной разметке и после первоначальной полной прошивки:

- Изменился только код: пересоберите проект и запишите `firmware.bin` по адресу `0x10000`.
- Изменились только звуки: пересоберите образ и запишите `spiffs.bin` по адресу `0x110000`.
- Изменились код и звуки: запишите оба файла.
- Изменились плата, разметка или параметры загрузки: используйте полную прошивку с заново проверенными адресами.

Запись `spiffs.bin` заменяет содержимое файловой системы целиком, а не добавляет отдельные файлы.

### Способ 2: PlatformIO напрямую

Установите [PlatformIO Core](https://docs.platformio.org/en/latest/core/installation/index.html) либо расширение PlatformIO IDE для VS Code. В случае расширения выполняйте команды в терминале PlatformIO. Docker и браузер для этого способа не нужны. Для первоначальной загрузки инструментов и зависимостей нужен интернет.

Соберите программу и образ звуков:

```powershell
pio run -e esp32-c3
pio run -e esp32-c3 -t buildfs
```

Подключите плату и найдите её порт:

```powershell
pio device list
```

Замените `COM5` на фактический порт. Загрузите программу, затем файловую систему:

```powershell
pio run -e esp32-c3 -t upload --upload-port COM5
pio run -e esp32-c3 -t uploadfs --upload-port COM5
```

PlatformIO определяет адреса и загружает необходимые служебные образы вместе с программой. Отдельно искать `boot_app0.bin` для этого способа не нужно. Образ звуков загружается отдельной командой `uploadfs`.

Если автоматическое подключение не сработало, переведите плату в режим загрузки кнопками **BOOT** и **RST**, как описано выше. После записи нажмите **RST**.

Для обновления только программы используйте `upload`, только звуков — `uploadfs`. Эти команды сами выполняют необходимую сборку. Полное стирание, когда оно действительно требуется:

```powershell
pio run -e esp32-c3 -t erase --upload-port COM5
```

После `erase` повторите обе команды загрузки. Подробнее: [загрузка файловой системы в PlatformIO](https://docs.platformio.org/en/latest/platforms/espressif32.html#uploading-files-to-file-system).

## Проверка после прошивки

Откройте последовательный монитор на **115200 бод**. Для PlatformIO:

```powershell
pio device monitor --port COM5 --baud 115200
```

При прошивке через браузер используйте раздел **Console** в ESP Tool. Не открывайте порт одновременно в браузере и другом мониторе.

1. Нажмите **RST** и подождите несколько секунд. В консоли должны появиться сообщения запуска.
2. Проверьте воспроизведение стартового сообщения.
3. Отправьте тревогу с совместимого передатчика и проверьте озвучивание нужной зоны.
4. Проверьте команду остановки и фоновые сообщения в отсутствие тревог.

Воспроизведение MP3 на реальном устройстве проверено пользователем. После изменения прошивки или аудиофайлов повторяйте проверку, в том числе при поступлении радиокоманд во время звука.

Для подробной диагностики аудио используйте [порядок проверки MP3](docs/mp3.md).
Для проверки кода без платы доступны [хостовые тесты](tests/host/README.md). Они не заменяют проверку звука, питания и радиосвязи на устройстве.
