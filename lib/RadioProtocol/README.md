# Общий радиопротокол

Один модуль для камер-передатчиков и спикеров-приёмников. Подключите весь каталог
`RadioProtocol` как локальную библиотеку в проект передатчика. Нужен RF24
(проверено с 1.6.2). Криптографические библиотеки не используются.

## Настройки

В [src/RadioSettings.h](src/RadioSettings.h):

```cpp
#define RADIO_GROUP_NAME "ALARM"
#define RADIO_CAMERA_COOLDOWN_MS 30000UL
```

Имя группы: 1..15 байт, рекомендуется ASCII, регистр учитывается.
У всех устройств группы должно быть одинаковое имя. Для другой группы задайте другое.
После изменения настроек пересоберите прошивку.

**Одна камера = одна зона**, номера 1..6. Камера отправляет команду своей зоны;
отдельных ID камер, сессий и номеров событий нет.

Спикер принимает не больше одной тревоги каждой зоны за указанный интервал.
Отсчёт начинается при приёме допустимой радиокоманды, до передачи менеджеру:
даже если очередь затем переполнена, интервал уже начался.
Отброшенные повторы не продлевают интервал. Другие зоны принимаются независимо.
Значение 0 отключает ограничение. Перезапуск очищает таймеры.
Это ограничение частоты: новая тревога той же камеры внутри интервала тоже игнорируется.

Остановка (99) принимается всегда, независимо от таймеров, и не сбрасывает их.
Ограничение применяется при приёме, а не от момента начала или завершения звука;
время воспроизведения зависит от очереди.

## Радио и формат версии 3

- Канал 76, скорость 1 Мбит/с, адрес `AZSPK` (5 байт).
- Фиксированная нагрузка 20 байт, CRC 16 бит.
- Dynamic payloads и auto-ACK выключены для групповой передачи.
- Байты 0..1: ASCII `AZ`; байт 2: версия 3; байт 3: команда.
- Байты 4..19: имя группы, дополненное нулями до 16 байт.
- Команды: числовые 1..6 для зон и 99 для остановки. ASCII-команд нет.

Все группы используют общий радиоадрес; приёмник сравнивает полное имя в пакете.
Пины, питание и мощность радиомодуля задаёт конкретное устройство.
Вызывайте `configureReceiver` или `configureTransmitter` после успешного `radio.begin()`.
Проверяйте результат настройки.

Это несовместимо с предыдущими версиями, включая HMAC-пакеты версии 2.
Обновите передатчики и приёмники вместе. Старый `RadioSecrets.h` не используется;
ключи и генератор настроек больше не нужны.

## Отправка

Пример интеграции для ESP32 после настройки SPI; объект `RF24 radio` создаёт приложение.
На каждой камере задайте её номер зоны.

```cpp
#include <RadioProtocolRF24.h>
#include <RadioSettings.h>
#include <esp_system.h>

constexpr RadioCommand CAMERA_ZONE = RadioCommand::ZONE_1_ALARM;
bool radioReady = false;

void beginRadio() {
    radioReady = false;
    if (!radio.begin()) return;
    radio.setPALevel(RF24_PA_LOW);
    radioReady = RadioProtocol::configureTransmitter(radio);
}

void sendCommand(RadioCommand command) {
    if (!radioReady) return;
    RadioProtocol::Packet packet;
    if (!RadioProtocol::encode(command, RADIO_GROUP_NAME, packet)) return;
    for (unsigned copy = 0; copy < 3; ++copy) {
        if (copy) delay(20 + esp_random() % 41);
        radio.write(packet.data(), packet.size());
    }
}
```

Тревога: `sendCommand(CAMERA_ZONE)`. Остановка: `sendCommand(RadioCommand::EMERGENCY_STOP)`.
Пример делает три отправки со случайными паузами; при положительном интервале,
превышающем длительность этих повторов, спикер пропустит повторные тревоги.
В рабочем приложении камеры можно заменить delay неблокирующим планировщиком.
Не вызывайте отправку из ISR.

## Границы

Имя группы **не является секретом или защитой от подделки**. Любой совместимый
передатчик с этим именем может отправить тревогу любой зоны или остановку.
CRC обнаруживает ошибки передачи, но не проверяет отправителя.
Защиты от намеренного повтора записанных команд, перегрузки или глушения нет.

Без auto-ACK результат `radio.write()` не подтверждает доставку или воспроизведение.
Повторы увеличивают вероятность приёма, но не гарантируют его всем спикерам.
Группы делят один канал и могут мешать друг другу.
Строго синхронного старта звука нет: занятые спикеры ставят тревоги в очередь.

## Проверка на платах

1. Задайте одинаковое имя группы на двух спикерах и передатчике.
2. Отправьте несколько тревог зоны 1 в пределах интервала: ожидается одна тревога.
3. Сразу отправьте зону 2: она должна приниматься независимо.
4. После интервала повторите зону 1: она должна приниматься снова.
5. Проверьте другую группу: команды игнорируются.
6. Проверьте остановку во время интервала и радиоприём при воспроизведении MP3.

Хостовые тесты проверяют формат, сравнение групп, таймеры зон, переполнение millis()
и настройки RF24. Они не заменяют проверку радиосвязи на устройствах.
