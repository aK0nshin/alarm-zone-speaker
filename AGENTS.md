# Правила проекта

- Общение и документация на русском.
- Ограничивать изменения текущей задачей.
- Не перезаписывать и не отменять незавершённые изменения пользователя.

## Стиль кода

- Придерживаться принципов SOLID. Разделять ответственность и зависимости без избыточных абстракций.
- Использовать ранний выход из функций для ошибок, некорректных входных данных и случаев, не требующих обработки. Избегать лишней вложенности.
- Оставлять минимум комментариев: только для неочевидных мест, причин решений и ограничений. Не пересказывать код комментариями.
- Следовать существующим соглашениям проекта об именовании и форматировании.
- Предпочитать штатные драйверы и проверенные библиотеки собственным декодерам, парсерам и обработчикам аудио.

## Поведение и границы

- Сохранять стартовое сообщение, последовательное озвучивание зон, вытеснение фоновой фразы тревогой и остановку с очисткой очереди.
- Хранить в очереди целые события тревоги: переполнение не должно оставлять обрывки сообщения.
- Разделять планирование сообщений, воспроизведение и радиосвязь. Менеджер зависит от TrackPlayer, а не от декодера.
- Не менять радиопротокол, интервалы фоновых фраз и набор зон без запроса. Не заменять текущие значения предполагаемыми значениями из старых комментариев.
- Общий радиопротокол находится в lib/RadioProtocol. Команды и настройки обеих сторон брать из него; совместимость проверять тестами. Версия 3: имя группы и команда, без HMAC, ключей и отдельных ID событий. Имя группы не защищает от подделки.
- Настройки RADIO_GROUP_NAME и RADIO_CAMERA_COOLDOWN_MS находятся в lib/RadioProtocol/src/RadioSettings.h. Одна камера = одна зона (1..6). Повторные тревоги зоны ограничиваются по времени приёма; отброшенные повторы не продлевают интервал. Остановка не ограничивается и не сбрасывает таймеры зон.
- Радио работает широковещательно, auto-ACK выключен. Не обещать гарантированную доставку, защиту от replay или синхронный старт звука. Не возвращать криптографию без запроса.

## Аудио

- Рабочий формат: MP3, моно, 24000 Гц, CBR 64 кбит/с, без ID3-тегов и Xing/LAME-заголовка.
- В data/ находятся только готовые MP3. Исходные материалы в data_src/ сохранять; WAV-плеер и dr_wav удалены, не возвращать их без запроса.
- Конвертация выполняется tools/prepare_mp3.sh через FFmpeg из исходников, не из ранее ухудшенных или сжатых копий. Скрипт перезаписывает десять целевых MP3.
- Декодирование выполняет закреплённая версия Helix, вывод через PDM с DMA штатного драйвера ESP-IDF. Не читать файлы и не декодировать звук из ISR.
- Не блокировать обработку радиокоманд на длительность трека. При смене декодера проверять размеры буферов, время обработки кадра и поведение при нехватке памяти.
- Сохранять корректную остановку, повторный запуск и завершение вывода хвоста аудио. Ошибку файла не выдавать за успешное воспроизведение.

## Железо и сборка

- Целевая плата: ESP32-C3 Super Mini.
- Окружение PlatformIO: `esp32-c3`.
- Для используемой платы требуется Flash Mode `dio`.
- Не менять распиновку и разметку Flash без согласования.
- Используется аналоговый усилитель LM4871, аудиовыход GPIO3. Не предполагать наличие внешнего фильтра и не назначать аудиотактовые сигналы на линии радио.
- Сохранять стек loopTask 16384 байта. Уменьшать только после измерений на плате; хостовые тесты ограничение стека микроконтроллера не воспроизводят.
- Файловая система SPIFFS. Не включать её автоматическое форматирование при ошибке монтирования.
- Не обновлять закреплённые зависимости попутно с несвязанными изменениями.
- Команды сборки и прошивки приведены в [README.md](README.md).

## Документация

- README описывает назначение и целевое поведение устройства, сборку и прошивку.
- Не включать в README временный статус разработки.
- Не дублировать в README детали реализации, которые часто меняются.

## Проверка

- После изменения кода проверять сборку.
- Команда сборки: `pio run -e esp32-c3`. После изменения data/ также выполнять `pio run -e esp32-c3 -t buildfs`.
- После изменения радио, плеера, очереди или зависимостей запускать [хостовые тесты](tests/host/README.md): `sh tests/host/run.sh` в окружении с gcc, g++ и FFmpeg, после установки зависимостей PlatformIO.
- Для аппаратной проверки использовать [порядок проверки MP3](docs/mp3.md). Успешная сборка и хостовые тесты не доказывают отсутствие заиканий, корректность радио или достаточный запас стека на ESP32-C3.
- Сообщать, какие проверки выполнены, а какие нет. При невозможности проверки указывать причину.
- Не прошивать подключённое устройство без явного запроса пользователя.
