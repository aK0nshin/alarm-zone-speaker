# Проверка MP3 на плате

Профиль файлов: MPEG Layer III, моно, 24000 Гц, CBR 64 кбит/с.
Плеер принимает только этот профиль, без ID3-тегов.
Файлы получены из data_src/v1, кроме phrase_01 из data_src/i-caught-an-olive.wav.
Генератор: tools/prepare_mp3.sh. Исходники сохранены в data_src/; data/ содержит только MP3.

Для проверки на плате:

1. Собрать программу и SPIFFS: pio run -e esp32-c3 и pio run -e esp32-c3 -t buildfs.
2. Загрузить оба образа по инструкции README, без полного стирания Flash.
3. Открыть монитор 115200 и проверить стартовое сообщение.
4. Проверить тревоги всех зон, вытеснение фона и команду стоп во время звука.
5. Проверить несколько циклов фоновых фраз на отсутствие заиканий и перезапусков.

После завершения или прерывания трека выводятся max decode и max read+decode
в микросекундах. Один кадр содержит 24 мс звука. Эти времена должны быть
существенно меньше 24000 мкс; сравнения только с длительностью кадра недостаточно:
нужен запас на радио, вывод и файловую систему. Отсутствие пропусков подтверждается
на плате, а не хостовым тестом. Пришлите также Loop stack minimum free.

Без Xing/LAME-заголовка плеер не компенсирует задержку кодировщика и заполнение
последнего кадра. В начале и конце коротких фраз возможны небольшие паузы.
Формат MP3 не устраняет шум аналогового усилителя и не заменяет фильтрацию PDM.

## Зависимость

Helix закреплён на f6e55a307c7577c5e3dfe1bf424a61075235fa08.
Используется C API MP3-декодера, без Audio Tools и без AAC.
Обёртка выделения памяти возвращает ошибку при нехватке памяти вместо зависания.
Лицензии стороннего кода: RPSL/RCSL для ядра Helix; сведения об обёртке
и лицензии находятся в репозитории https://github.com/pschatzmann/codec-helix.
